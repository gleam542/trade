# signalbench

**從 K 線算技術訊號，並誠實檢驗它值不值得相信。**

抓 Binance 的 K 線存進 PostgreSQL，用五項技術指標計分產生多空訊號，然後——這才是重點——用走查式回測告訴你這些訊號在歷史上到底有沒有用。附一個 HTTP API 與網頁介面。

## 這個專案做什麼

| | |
|---|---|
| **收資料** | Binance 現貨與 USDT 本位永續合約的 K 線，五百多個交易對，存進 PostgreSQL |
| **算指標** | RSI、MACD、布林通道、KD、費波那契回撤、ATR、EMA——全部純 Python 手算，沒有 TA-Lib 之類的依賴 |
| **產訊號** | 五項指標各 ±1 分加總定方向，再過一道長期 EMA 趨勢過濾擋掉逆勢單 |
| **驗訊號** | 走查式回測，逐根 K 線重算、不看未來資料，並列出 buy & hold 作為對照 |
| **找標的** | 跨全市場掃描，附樣本數門檻與多重比較的防護 |
| **看結果** | FastAPI + 單頁前端，圖表、指標、回測、策略試算都在同一個 port |

## 這個專案不做什麼

**不下單。** 沒有任何交易所的下單串接，也不打算做。

**不宣稱能賺錢。** 實測 10 支合約各約 500 根 1 小時 K 線，加上趨勢過濾後平均總報酬從 −2.49% 變成 +5.23%、勝率 53.6% → 60.8%——但**兩種設定都沒有贏過單純買入持有**（那段期間 buy & hold 有 12~41%）。這個數字就寫在文件裡，因為隱瞞它才是這類工具最常見的毛病。

**不假裝統計上很可靠。** 跨市場掃描五百多個標的再挑「數字最好的那個」，是典型的多重比較陷阱：25 筆交易拿到 60% 勝率純靠運氣就有 21.2% 的機率，掃幾十個候選幾乎必然出現一個看起來很棒的。所以加了樣本數門檻、把歷史為負的排到最後，並且在畫面上標明排除了幾個——但這些護欄擋掉的是雜訊，不會變出訊號。

**不構成投資建議。** 所有輸出都是指標的算術結果與歷史統計，不是預測。

## 開始使用

程式與完整說明都在 **[`trade-signal/`](trade-signal/)**。

```bash
cd trade-signal
pip install -r requirements.txt
python main.py                                  # 抓資料
python -m uvicorn api:app --port 8000           # API + 網頁介面
```

然後開 <http://localhost:8000/>。

詳細的指標算法、參數、回測方法、部署與排程設定見 [trade-signal/README.md](trade-signal/README.md)。
